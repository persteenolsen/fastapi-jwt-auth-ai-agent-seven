New Project – FastAPI, Vue, Vercel, Neon and Simply.com MCP

Step-by-step implementation plan

1. Create a new GitHub repository

Create a separate repository.
Copy the working FastAPI + LangChain + Simply.com baseline.
Keep the original project untouched.

2. Prepare FastAPI for Vercel

Add vercel.json and the appropriate FastAPI entry point (app.py or index.py).
Configure Python dependencies and deployment settings.
Ensure Vercel can correctly run the FastAPI application.

3. Create a Neon PostgreSQL database

Use Neon for persistent storage:

Users and application data.
Simply.com OAuth tokens and client information.
Token expiration timestamps and OAuth state.

Use SQLAlchemy, Neon's pooled connection string and encrypted storage for sensitive credentials.

4. Configure Vercel environment variables

Store deployment secrets and configuration in Vercel:

DATABASE_URL
GROQ_API_KEY
JWT_SECRET_KEY
Simply.com configuration.

Neon stores persistent data and OAuth credentials; Vercel stores deployment secrets. Never commit secrets to GitHub.

5. Adapt Simply.com OAuth authentication

This is the most important architectural change.

The current implementation uses a separate local HTTP callback server:

http://localhost:3030/callback

This approach must be replaced for the Vercel deployment.

New OAuth architecture

Instead of starting a separate callback server, create a dedicated FastAPI endpoint:

https://your-domain.vercel.app/simply/oauth/callback

The authorization flow will work as follows:

The user starts initial Simply.com authorization through a protected Swagger endpoint.
FastAPI initiates the OAuth authorization process.
Simply.com returns an authorization URL.
The user is redirected to Simply.com in their browser.
The user approves the requested permissions.
Simply.com redirects the browser to the public FastAPI callback endpoint.
FastAPI receives the authorization code and OAuth state.
FastAPI validates the OAuth state.
FastAPI exchanges the authorization code for access and refresh tokens.
FastAPI securely stores the OAuth credentials in Neon PostgreSQL.
The user receives confirmation that authorization was successful.

The redirect URI must be registered with Simply.com and must exactly match the URI configured in the OAuth client registration.

For example:

https://your-domain.vercel.app/simply/oauth/callback

Important implementation details
Use HTTPS for the public callback.
Generate and validate a unique OAuth state for every authorization attempt.
Store temporary authorization state securely in Neon or another persistent store.
Never rely on in-memory callback queues or local HTTP servers.
Encrypt OAuth tokens before database storage.
Never expose authorization codes, access tokens or refresh tokens in API responses or logs.
Make the callback endpoint compatible with Vercel serverless execution.

6. Adapt SimplyOAuthManager for serverless execution

Load OAuth credentials from Neon.
Handle expiration, automatic refreshing and refresh-token rotation.
Persist updated credentials immediately.
Replace reliance on in-memory asyncio.Lock with database-level locking and transactions to protect against simultaneous refreshes from multiple serverless instances.

7. Adapt SimplyMCPClient

Preserve the existing architecture:

Obtain valid OAuth tokens.
Connect to Simply.com MCP.
Discover and execute approved read-only tools.
Initially enable list-accounts and list-subdomains.

8. Deploy the Vue frontend

Deploy Vue through Simply.
Connect it to FastAPI.
Configure production API URLs, CORS and JWT authentication.

9. Test the complete application

Authentication: Login, JWT, initial OAuth authorization, public callback, state validation and Neon credential storage.

OAuth management: Credential loading, automatic refreshing, refresh-token rotation, concurrent refresh protection and persistence across serverless instances.

Simply.com MCP: Tool discovery, list accounts and list subdomains.

AI integration: Groq, LangChain agent, Wikipedia and Simply.com tools.

Deployment: Test all endpoints, authentication after redeployment and OAuth refreshing without restarting the application.

Final architecture

GitHub: Source code and version control.
Vercel: Vue frontend and FastAPI backend.
Neon PostgreSQL: Persistent application data and encrypted OAuth credentials.
Groq: LLM provider.
LangChain: Agent framework.
Simply.com: MCP server and OAuth provider.

Development principle: Use the existing working baseline. Adapt one component at a time, test it, and preserve the working Simply.com integration wherever possible.
